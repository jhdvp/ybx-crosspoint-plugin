## Матрица возможностей

| Область | Реализация | Оговорки |
| --- | --- | --- |
| QR / device-code авторизация | Есть | При потере `token.json` требуется повторная привязка |
| Яндекс Книги: четыре полки и поиск | Есть | Нужна подключённая библиотека в YBX |
| WB Книги: полка и EPUB | Есть | Не все книги источника доступны к выгрузке |
| ЛитРес в собственных полках | Есть (с 1.6.14 RC, в stable с 1.6.17) | Приобретённые EPUB могут быть доступны через OPDS отдельно |
| Скачивание EPUB | Есть | Права и ограничения поставщика действуют |
| Читательский веб-профиль | Есть | Минуты, серия, календарь, цель года, достижения |
| Экран сна YBX | Есть | Пользователь включает добровольно, картинка требует поддержки firmware |
| Сохранение настройки сна при обновлении | Есть | При полной замене папки плагина локальные данные могут быть потеряны |
| KOSync через плагин | Есть | Отдельный `kosync_`, сервер `http://sync.ybx.app`; HTTP не шифруется |
| Ручной KOSync аккаунта | Есть | Независимые логин и пароль из кабинета |
| Двусторонний KOSync на настоящем X4 Pro | **Не подтверждено** | Нужен реальный GET / Apply Remote и сопоставление EPUB |
| Экспорт vCodex-статистики | Есть | Процедура импорта определяется прошивкой; осторожно с существующими данными |

## Подготовка релиза 1.6.18

Статус: **подготовлена локально, ожидает публикации корневым репозиторием**.
Стабильным остаётся 1.6.17; 1.6.18 ещё не опубликована и не объявляется
проверенной на каждом устройстве.

- **Суть исправления:** пагинация на CrossPoint 2.0.0 и совместимость со старой
  схемой lookahead. Все каталожные URL (основной каталог, поиск, восемь полок)
  объявляют `page_size=10`; `limit` остаётся плейсхолдером, который прошивка
  подставляет сама: 10 на 2.0.0, 11 в старых сборках с lookahead. Сервер берёт
  шаг выборки из `page_size`, поэтому оба варианта видят по 10 книг на страницу.
- Авторизация, события и скачивание EPUB маркера `page_size` не получают.
- Плагины со старыми байтами без `page_size` на 2.0.0 нужно обновить.
- Состав полок, QR-вход, KOSync, экран сна и capabilities не меняются; в 1.6.18
  нет Native-возможностей (`catalog.lists.auth`, `catalog.folders.json`, …).
- **Проверка:** полный Python unittest, `node --test tests/*.mjs`, сверка с
  каноническим исходником, воспроизводимая сборка ZIP и HTTP-тесты корневого
  репозитория. Это не аппаратная приёмка: реальный GET/Apply Remote и работу на
  физическом X3/X4/X4 Pro по-прежнему нужно проверять отдельно (см. Roadmap).

Подробности: [RELEASE-1.6.18.md](RELEASE-1.6.18.md).

## Что исправлено в 1.6.13 и 1.6.12

- **1.6.13:** статистика веб-панели запрашивается напрямую браузером по HTTPS. Не требует TLS-соединения ESP32, но необходим интернет на телефоне и поддержка CORS на сервере.
- **1.6.12:** отзыв старых ключей после *успешного* обмена позицией, а не в момент ошибки или проверки логина.
- Переходный период 15 минут при успешном использовании нового ключа.
- Сохранение обработчика `sleep.enter` при обновлении внутри веб-панели и сохранение пользовательского выбора при внешней замене релизных файлов, если настройка уцелела.
- Безопасное снятие старой карточки и защита `sleep-legacy.bmp` от перезаписи.

**Проверка релиза:** целевые тесты plugin.js и KOSync, сверка runtime payload с серверной раздачей, CI и production smoke. Физический X4 Pro этими проверками не заменяется.

## Roadmap

1. **Приоритет 1:** проверить реальный двусторонний KOSync на X4 Pro с CrossPoint 2.0, включая разные EPUB одной книги.
2. **Приоритет 1:** после публикации 1.6.18 подтвердить пагинацию на физическом CrossPoint 2.0.0 и на старой прошивке с lookahead (HTTP-тесты это не заменяют).
3. **Приоритет 1:** подтвердить сохранение токенов и настроек при обновлении через Plugin Hub.
4. **Приоритет 2:** не менять нестандартные режимы сна сторонних прошивок без явной проверки совместимости.
5. **Приоритет 2:** уточнить процедуру экспорта vCodex и предупреждения перед перезаписью данных ридера.
6. **Приоритет 3:** симуляторные скриншоты меню и кнопочной навигации X3/X4 как воспроизводимый тестовый артефакт.

Результаты аппаратного теста можно прикладывать к [issue](https://github.com/jhdvp/ybx-crosspoint-plugin/issues).
