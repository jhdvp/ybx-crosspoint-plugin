# Решение проблем

[← На главную](../README.md) · [Установка](INSTALL.md) · [Статус](STATUS.md)

### Позиция уходит с ридера в Яндекс, но не возвращается

Проверьте **не только источник книг**, но и именно настройки KOSync. Встроенное зеркало CrossPoint Sync может пересылать прогресс в YBX, не запрашивая обратную позицию. Откройте веб-панель YBX через `http://crosspoint.local/plugins`, настройте KOSync, проверьте статус авторизации и выполните `Sync Progress` на ридере. Серверный `200` на отправке не означает успешного применения удалённой позиции.

### На CrossPoint 2.0 нет раздела YBX в настройках

Панель плагина открывается **в браузере**, а не обязательно отдельным пунктом системного меню. Включите Wi-Fi, File Transfer, затем откройте `http://IP-ридера/plugins` с устройства в той же сети. Проверить наличие `plugin.js` рядом с `device.json` в папке YBX.

### После обновления пропал вход

Если установщик заменил всю папку `ybx`, файл `token.json` мог исчезнуть. Повторите привязку по QR. Пожалуйста, не публикуйте токен или пароль в issue.

### Статистика YBX заменила мои обои

Начиная с 1.6.12 статистика добровольная. В веб-панели отключите её. Если в `/sleep.bmp` осталась старая карточка без метки YBX, используйте ручную очистку с подтверждением и резервной копией. Не удаляйте файл, не убедившись, что это действительно карточка YBX.

### После обновления опять нужно включать статистику

1.6.12 сохраняет выбранный режим при обычном обновлении из веб-панели. При полной замене всех данных плагина через сторонний установщик файл `sleep-preference.json` может потеряться. Его сохранение зависит от способа обновления.

### Можно ли безопасно перезаписать локальную статистику?

В версии 1.6.12 выгрузка vCodex может предложить замену уже существующего файла
`/.crosspoint/reading_stats.json`. Перед подтверждением сохраните копию локальных данных
на компьютер. Автоматическое объединение статистики в YBX Plugin не заявлено.

### Какие данные приложить к issue?

Модель ридера, точная версия прошивки, версия плагина (например, 1.6.13), путь установки, последовательность действий, ожидаемый и фактический результат, скриншот. **Не прикладывайте токены, QR-привязки и пароли.**

### Статистика не загрузилась после перехода на 1.6.13

Проверьте доступность https://my.ybx.app **на телефоне**. Статистика в
веб-панели запрашивается браузером напрямую по HTTPS; если телефон работает
только в Wi-Fi ридера без выхода в интернет, запрос не пройдёт. Повторная
привязка ридера не нужна. Если браузер сообщает CORS, укажите в issue
локальный адрес ридера и точную версию плагина без публикации токенов.

## Резервные EU-адреса

Веб-панель `plugin.js` повторяет запрос при подтверждённом транспортном сбое
на парном адресе: `my.ybx.app` → `emy.ybx.app`, `opds.ybx.app` →
`eopds.ybx.app`, `sync.ybx.app` → `esync.ybx.app`. Схема, путь, параметры,
метод, тело и заголовки сохраняются. HTTP-ответы, включая 401, 429 и 5xx,
не вызывают переключение. Ошибки чтения JSON и записи на SD также не являются
основанием для переключения. Неудача обоих адресов завершает запрос ошибкой.

Рабочий адрес запоминается до закрытия/перезагрузки панели, отдельно для
браузера и сетевого стека ридера и для каждой пары адресов/схемы.
Через пять минут следующий запрос снова пробует основной адрес. Если он
недоступен, запрос повторяется на зеркале. Без открытой панели таймеры и
фоновые проверки не запускаются. OAuth/callback и ссылки входа не меняются.

**Ограничения Stock-прошивки:** `device.json` оставлен без изменений.
Её `RequestSpec` читает единственную строку `url`, а не список резервов:
см. `src/util/PluginHttp.cpp` (`readRequest`) и
`src/activities/plugins/PluginCatalogActivity.cpp` в исходниках CrossPoint.
`browse.lists` позволяет добавить отдельные ручные EU-полки, но это не
резервный маршрут для QR-входа, поиска, скачивания или событий. Поэтому
дублирующие полки и неподдерживаемые поля `fallback_url` не добавлены.
Автоматическое переключение этих операций и фонового KOSync требует
поддержки в самой прошивке; JavaScript панели их не перехватывает.

У `/api/relay` есть дополнительное ограничение: прошивка сводит сетевой сбой,
обрезанный/слишком большой ответ и нехватку памяти к одной ошибке
`502: relay failed; large bodies need /api/fetch`. Панель не переключает
адрес по этой неоднозначной ошибке. Подтверждённые транспортные результаты
(`status <= 0`, `transport failure`) поддерживаются; `/api/fetch` их возвращает.
Для полного покрытия relay прошивка должна отдельно сообщать причину сбоя.
